# Held patches 0009, 0012, 0013 and 0015: superseded

fastppcx86 landed 0001–0008, 0010, 0011, 0014 and 0016. They landed 0007 with a
fix of their own: the argv[0] path called `pop_back` on an empty vector when
the guest passed a NULL envp. They held four patches after review. Each one is
replaced by a v2 patch that holds the original change plus the fix:

| Held | Replaced by | Review point | v2 change |
|---|---|---|---|
| 0009 | `0018-v2-Syscalls-return-EFAULT-for-bad-guest-path-utsname-an.patch` | The ppc64le path copy was a byte loop over the rest of a 4K page, about 1 µs per open or stat | A word-at-a-time copy that stops at the NUL and faults only where the kernel would. 1e6 x86-64 `stat`: 3.91 s → 1.29 s |
| 0012 | `0019-v2-FEXInterpreter-FileManager-keep-FEX-s-own-descriptor.patch` | Descriptors went below the soft NOFILE limit, so after Wine raised it every child had a multi-megabyte fd table | Descriptors go below min(soft limit, 1024). With the soft limit raised to 524288, FDSize is 1024 (was 524288), and the first open is still 3 |
| 0013 | `0020-v2-ForkGuest-copy-a-vfork-CLONE_VM-child-s-memory-back-.patch` | The copy-back used memcpy with signals blocked into SMC-armed read-only granules, so a 64K guest died on its first vfork | Writes go through `/proc/self/mem` and are then invalidated. If the kernel refuses a forced write, the tracker disarms, invalidates and unprotects the granule (`UnprotectGuestRangeForHostWrite`) first. RWX mappings are copied too |
| 0015 | `0021-v2-FEXInterpreter-hold-log-messages-until-the-log-desti.patch` | Buffering hid FEXServer and rootfs errors under the default silent logging | Error-level messages are still held and go to stderr when start-up fails or the guest exits nonzero. A successful run stays silent. "empty rootfs path" is logged only for an image rootfs |

The v2 patches apply in order on `fastppcx86/daedalao-wt` (9da3ccf9f) with
the landed patches and their NULL-envp fix already applied. Each commit message
has before/after evidence from a static x86-64 guest on the 64K host with
`FEX_HOSTPAGEMODE=force`.

Two points from their review need no patch here. Link-first exits and direct
conditional exits already match how fastppcx86 does exits. The 2.6% bst
regression looks like far-link placement, which is being worked on separately.

The same fixes are in POWERarm as `powerarm/fix:` commits on
`powerarm-fix/patch-rework`, with the NULL-envp fix and A64Syscalls
regression tests (`sys_process`, `sys_errno`).
